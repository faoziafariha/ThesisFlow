# 📚 Thesis & Project Management Portal  
### *A Full-Stack Academic Workflow Management System*

---

## 📌 Overview

The **Thesis & Project Management Portal** is a full-stack web application designed to simplify and centralize all academic project workflows for students, supervisors, and administrators.

It provides a modern, streamlined platform for:

- Managing thesis/project proposals  
- Tracking progress, deadlines, and submissions  
- Communication between students and supervisors  
- Maintaining academic documents and resources  

This system was developed as part of the **Software Engineering Sessional (CSE)**, showcasing industry-grade engineering practices, modular architecture, and clean frontend-backend integration.

---

## 🎯 Core Objectives

- Build a scalable, maintainable system following **Software Engineering principles**  
- Apply **modular design**, **version control**, **testability**, and **documentation**  
- Enable students and supervisors to manage entire thesis cycles in one platform  
- Support automated workflows and structured academic processes  
- Implement **secure, efficient, user-friendly** interactions

---

## 🧠 Software Engineering Practices Applied

### ✔ **Requirements Engineering**
- Collected functional & non-functional requirements  
- Developed use cases, user stories, and workflow diagrams  
- Identified system constraints and actors (Student, Supervisor, Admin)

### ✔ **System Design**
- Layered architecture:  
  - **Frontend Layer** (UI logic)  
  - **API Layer** (communication)  
  - **Backend Logic Layer**  
  - **Database Layer**

- Adopted **separation of concerns** and **single responsibility principle**  
- Designed entity relationships & normalization (ERD included in documentation)  

### ✔ **Version Control & Collaboration**
- Git-based workflow with:
  - Structured commits  
  - Feature branches  
  - Merge review discipline  
- Collaborated using GitHub pull requests and version traceability

### ✔ **Testing & Quality Assurance**
- Automated test flows using Playwright  
- Classname refactoring for test stability  
- Manual testing of key workflows (login, dashboard, project creation)

### ✔ **Documentation**
- Full SE-style report including:
  - SRS (Software Requirements Specification)  
  - SDS (System Design Specification)  
  - Test cases  
  - UML diagrams  
  - Architectural descriptions

## 🗄 Database Architecture

The system includes well-structured relational tables:

- **Users** (Student, Supervisor, Admin)  
- **Proposals**  
- **Submissions**  
- **Reviews**  
- **Schedule / Deadlines**  
- **Notifications**  

Each table is normalized to reduce redundancy and ensure efficiency.
